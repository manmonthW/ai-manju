# AI Comic Drama Pipeline

Produce a multi-shot AI comic drama from screenplay to verified delivery. Hermes owns contracts, continuity, approval, job state, QA and files; Lovart supplies image and video generation only.

## When to Use

- Use for serial comic dramas with recurring identities, props and locations.
- Use when paid generation must be resumable, auditable and cost-controlled.
- Use when static keyframes, I2V, deterministic editorial motion and reused footage must share one production ledger.
- Do not use for a one-off image with no continuity or downstream delivery.

## Prerequisites

- Load `lovart-windows-chrome` before operating Lovart.
- Work in a project directory outside the skill directory.
- Verify the dedicated Windows Chrome profile, reverse tunnel and current Lovart project before every production session.
- Keep credentials in the browser; never export cookies, tokens or passwords.
- Obtain exact paid-job approval unless the user has granted a bounded standing authorization. A standing authorization never permits buying credits or upgrading a plan.

Completion criterion: the current Lovart page is logged in, the project ID is known, and the approval scope is recorded.

## Authority and Contracts

Hermes is authoritative for screenplay, asset bible, shot contracts, Prompt IR, reference order, approval hashes, job events, checksums, QA and delivery manifests. Lovart is authoritative only for live models, parameters, prices, balances, provider IDs and generated bytes.

Use stable IDs:

- scene: `EP001-SC001`
- shot: `EP001-SH001`
- image job: `JOB-EP001-SH001-I01`
- video job: `JOB-EP001-SH001-V01`

Keep project-relative paths and reject secret-like contract fields. Never treat a canvas node, chat message or stale Done result as the production ledger.

## Job State Machine

Successful paid work follows:

```text
draft → reviewed → approved → queued → submitted
→ collecting → generated → qa_passed → accepted
```

Use `rejected` when media exists but continuity or narrative QA blocks it. Use `failed` for provider, moderation or collection failure. Preserve historical QA when the user accepts a blocked asset; represent that decision in a waiver manifest rather than rewriting a PASS.

Rules:

1. Preview hashes bind immutable prompt, model, parameters, reference order and outputs.
2. Queue consumes approval exactly once.
3. Submitted jobs collect before retry; slow generation is not permission to resubmit.
4. `generated` means verified bytes, not creative acceptance.
5. Only accepted or explicitly waived assets may enter downstream work.
6. Every result records provider ID, actual cost, balance delta, dimensions/duration and SHA-256.

## Procedure

### 1. Lock Story and Shot Boundaries

For every shot define story purpose, start boundary, one primary transition, stable end boundary, camera rule, continuity locks and forbidden failures. Keep one editable authority for each fact.

Completion criterion: every shot has a stable ID and resolves all referenced assets.

### 2. Build the Asset Bible Economically

Create one accepted front identity anchor before optional views. Assign one owner to each continuity trait: character identity, costume, prop topology, location geometry and lighting. Stop regenerating full multi-view sheets after two failed passes; derive constrained views or document a waiver instead.

Completion criterion: every continuity-critical trait has one accepted authority.

### 3. Generate Static Keyframes by Risk

Generate the hardest identity/hand/prop/camera combinations first. For every frame:

1. Clear previous Lovart references.
2. Upload in declared order.
3. Read back the right-side reference count and thumbnails; a DOM node or left-chat attachment is not proof of binding.
4. Read back model, parameters, live cost and balance.
5. Submit once, collect, download, hash and inspect.
6. Write an approved or waiver manifest with actual frame traits and downstream constraints.

Completion criterion: all new-image shots have an accepted frame and manifest; reuse shots resolve to verified source footage.

### 4. Preview and Submit Paid Jobs

Record job ID, exact prompt, ordered reference roles, model, parameters, output path, live price, balance and deterministic preview hash. Under bounded standing authorization, execute without another question but keep the same preview and ledger steps.

After Generate, verify either a new provider node or a balance change and record the provider ID immediately.

Completion criterion: state is `submitted` with a non-empty provider ID and no duplicate click.

### 5. Collect Before Retry

Inspect all completed image/video shapes because Lovart may replace a task placeholder instead of updating it. Download originals and verify:

- image: format and pixel dimensions;
- video: duration, dimensions, frame rate, codecs, streams and size via `ffprobe`;
- all media: SHA-256 and actual credit delta.

Completion criterion: state is `generated` and metadata is recoverable from disk.

### 6. Run Strict Static QA

Check identity markers, anatomical sides, crown/hairpin/belt/garment topology, prop count, hand separation, location axis, lighting, unwanted text, watermark and modern objects.

User-directed approval does not erase defects. Record actual deviations and lock the generated facts that downstream animation must preserve.

Completion criterion: accepted/waived status and manifest agree with the original QA evidence.

### 7. Choose I2V or Deterministic Motion

Use paid I2V only when the shot requires causal physical motion that cannot be delivered by controlled 2.5D editing. Use deterministic push-ins, parallax, overlays and restrained reaction animation for dialogue shots.

Before I2V, test the riskiest shot first. Assign one primary motion objective. Do not ask one clip to execute multiple independent beats such as drop → pick up → match cut; split them into separate clips or an editorial cut.

Completion criterion: the selected motion method is recorded for every shot before batch spending.

### 8. Handle Model Capability and Moderation

Model selection is live capability discovery, not a permanent assumption:

- confirm the chosen model accepts the bound image and target aspect ratio;
- if Generate becomes disabled after binding, treat the model as incompatible rather than forcing text-to-video;
- if moderation rejects an original fictional frame, record a provider-policy failure and zero/actual charge; do not mislabel it as creative rejection;
- do not blindly rerun the same rejected model. Try a compatible Lovart model or split the shot.

Completion criterion: a replacement job has a new preview hash, or the shot is switched to deterministic editing with a documented reason.

### 9. Run Temporal I2V QA

A downloaded video is not accepted until all checks pass:

1. Verify with `ffprobe`.
2. Generate a time-ordered contact sheet plus first, critical-action and final frames.
3. Inspect start-frame continuity, causal action, prop count, hand contact, identity, costume, background, pseudo-text and end-frame editability.
4. Inspect sub-second critical frames when the action is fast.

Reject clips with transient duplicate props even when the final frame looks correct. Reject an end frame that does not show a stable completed action.

Completion criterion: `generated → qa_passed → accepted`, or `generated → rejected` with time-coded issues.

### 10. Assemble and Verify Delivery

Retime reused footage deliberately, remove empty audio streams, replace important pseudo-text in post, then assemble picture, voice, music, effects and subtitles. Verify final duration, dimensions, codecs, audio, subtitle safety, shot order and delivery checksum.

Completion criterion: the final file passes media inspection, all  shot sources resolve, and a delivery manifest records provenance and acceptance.

## Prompt Discipline

- One primary action per generated clip.
- Describe start state, physical transition and stable end state.
- State which anatomical hand owns and stabilizes each prop.
- Use references as scoped owners; identity references must not redefine backgrounds.
- Keep camera movement restrained unless it is the shot's main transition.
- Keep pseudo-text soft and replace important readable text deterministically.
- Prioritize identity, anatomy, prop count and causality over long negative-prompt lists.

## Cost Discipline

- Use Lovart as the only media backend.
- Read live cost immediately before submission; never reuse stale pricing.
- Record balance before and after, including zero-charge moderation failures.
- A revision is a new job and hash.
- After two whole-frame failures, change strategy: split the shot, use a local repair, use deterministic motion or request a documented waiver.
- Test one risky I2V before batching the episode.

## Pitfalls

- Reference images uploaded to the left Agent chat are not bound to the right generator.
- Hidden or virtualized canvas nodes do not prove reference binding.
- A user approval is not a technical PASS.
- A clean final video frame can hide a duplicate prop in an earlier half-second.
- Complex rigid props often deform during I2V; inspect shape stability over time.
- An I2V model may accept a prompt but reject the image during moderation.
- A model shown in Lovart may support text-to-video but disable generation with an image reference.
- Empty AAC tracks can appear when audio is disabled; verify streams and remove them in post.
- Do not commit credentials, browser state or machine-local paths.

## Verification

A production gate passes only when:

- contracts and state-machine tests pass;
- every static shot is accepted, waived or backed by verified reuse footage;
- at least one real I2V clip passes temporal QA before batch generation;
- every paid attempt has hash, provider ID, cost, balance delta and terminal state;
- all generated media has verified technical metadata and checksums;
- rejected attempts remain recoverable as evidence but cannot silently enter delivery;
- final assembly passes duration, stream, continuity and delivery-manifest checks;
- no credential, cookie or secret is present in project files.
